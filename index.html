Pick of the week

LongCat-2.5: Meituan's 1.6T native-multimodal model built for long-horizon agent work

Meituan released LongCat-2.5, a 1.6-trillion-parameter MoE (about 48B active per token) for long-horizon agentic tasks. Visual signals become multi-level discrete tokens in the same stream as text, so one backbone does native visual understanding plus agentic coding; training uses large-scale long-horizon RL over long trajectories, mixed across harnesses, and - the interesting part - a pipeline that converts real agent failure trajectories into reproducible, verifiable training tasks. It was trained and runs W4A4 inference on domestic Chinese accelerators, with numerical consistency kept between training and inference. Launch benchmarks compare against GPT-5.5, GPT-5.6-Sol, and Claude Opus 4.8/5 - vendor numbers; the post does not say whether 2.5 weights are downloadable yet.

Why it matters: Two ideas to steal. First, failure-trajectory-to-verifiable-task is a concrete recipe for turning your own eval failures into training data - exactly the loop a capstone on evaluation reliability wants. Second, 'mixed training across harnesses' treats the harness as a first-class training variable, the same sensitivity last week's sys1-eval pick measured. Also a frontier-scale agentic-coding datapoint from outside the usual US labs, trained end-to-end on non-Nvidia silicon.

From production: the autoscaler that sized the cluster to zero before its first request

From productionWeb

A capacity-planning simulator for LLM serving (BLIS, built for parity with the llm-d Kubernetes stack) completed 0 of 200 requests in a test run: its autoscaler ticked at t=0, saw no load, and drained all four warm replicas 50ms before the first request arrived. The author filed the bug and a fix (both open with the inference-sim project) and shows the general lesson - an autoscaler that sizes a cluster to its demand will size it to zero at zero demand unless something sets a floor.

Why it matters: If you plan GPU capacity with a simulator, the simulator's autoscaler policy is part of your plan - verify its floor, tick timing, and warm-start assumptions before trusting its GPU counts. Same lesson transfers to real K8s autoscaling of inference endpoints: min-replica floors and cold-start-aware routing are not optional when scale-to-zero is on the table.

Anthropic's amended S-1: $17B quarter, $23.3B loss, $895B compute tab

IndustryWeb

Anthropic amended its S-1 (SEC filing November 2) with the first hard numbers from a frontier lab: Q3 revenue of $17.0 billion, up ~1,127% year over year but with quarter-on-quarter growth slowing to 47% (from 144% in Q2 and 132% in Q1); a net loss of $23.29 billion for the quarter; and aggregate purchase and lease commitments of about $895.4 billion, nearly all compute and infrastructure (up from the $417 billion listed in the original filing). Compute and infrastructure expense hit $14.4 billion for the nine months to September 30, up 329%.

Why it matters: This is the first audited-grade look at frontier-lab economics: revenue is real and growing triple digits, but the loss and the $895B forward compute commitment show the business is a bet on capacity years ahead of demand. When you read vendor pricing or model-deprecation decisions from now on, this cost structure is why - and it is the benchmark every other lab's rumored numbers will be judged against.

Build Claude Code from scratch: a free harness-engineering course (8 parts, code included)

CraftWeb

Decoding AI turned months of dissecting Claude Code, OpenCode, and Pi into a free, open-source harness-engineering course: 8 articles, 6 videos, and one codebase in which you build a working coding agent (Decode) step by step - agent loop, sandboxing, four context-engineering techniques, subagents, headless cloud deployment, custom benchmarks, and replaying failed runs to debug. It cites LangChain's harness-only swap going from 53% to 67% on Terminal-Bench (same model, outside the top 30 to top 5) and Ramp's claim that roughly half its merged PRs now come from a custom harness - both their numbers, worth treating as directional.

Why it matters: The agent is ~20 lines; everything above it is the harness, and the harness is where quality, cost, and reliability actually live - the same conclusion last week's sys1-eval pick measured. If you build or evaluate agents, the custom-benchmark and failed-run-replay lessons map directly onto capstone-grade evaluation methodology, and building one harness end-to-end is the fastest way to make eval results legible.

Beacon: an open-source memory layer so coding agents learn from past sessions

AgentsWeb

Asymptote Labs launched Beacon on Product Hunt today: an open-source memory layer that records execution traces from your coding agents - commands, file changes, errors, debugging paths - and distills them into reusable knowledge (successful fixes, recurring workflows, lessons), shared across Claude Code, Cursor, Codex, OpenCode, Cline, and 20+ other harnesses, with per-harness agent skills and an OTLP-based collector. The pitch: the debugging breakthrough your agent found yesterday should still be known tomorrow, whichever agent you open.

Why it matters: Memory is becoming the third layer of the agent stack after model and harness - and cross-harness memory is a bet that no single harness wins. The claims are launch-day vendor claims, but the repo is real and active (3,000+ commits). If your agents repeat mistakes across sessions, this is worth a local try; it also pairs with LongCat-2.5's failure-trajectory learning as the same idea at product level.

FlashProve: Anthropic open-sources zkSNARK proofs that the model you called is the one that answered

ResearchSecurityWeb

Anthropic's Frontier Red Team released FlashProve, an open-source prototype for provable inference: the provider commits to the weights up front, then attaches zero-knowledge proofs so anyone can check on a CPU that the committed model produced those exact tokens - catching routers that silently swap in cheaper models or tampered servers. Measured on Llama 4 Maverick (400B MoE, ~17B active per token, public 4-bit weights): a prover with one H100 plus 24 CPU cores proves a batch of 24 requests in ~223 seconds (~110 tokens/second, ~19 MB proof each), roughly 72-94x the per-GPU time vLLM takes to serve the same batch (on eight H100s, FP8); the client downloads a ~6.5 MB commitment and checks each proof in ~17 seconds on CPU. Scope limits worth knowing: proving is post-hoc (batched, after the fact, not inline with serving), covers windows of up to 1,024 tokens, and asserts the integer 4-bit model under greedy decoding - floating-point or sampled serving can legitimately depart. Claude wrote much of the system; completeness, soundness, and zero-knowledge are machine-proved in Lean, and the prover, C++ and Lean verifiers, spec, and technical report are all Apache 2.0 on GitHub.

Why it matters: Model substitution is a real trust gap - if you pay for a frontier model through a router or run evals against an API, you take the model's identity on faith today, and output quality cannot prove it. Context for the speed claim: the prior open proof of this same model (VerInf) managed ~0.02 tok/s with a 93.6 GB proof that took almost a day to verify; FlashProve is thousands of times faster with proofs checkable in seconds. Still a research prototype (short windows, greedy decoding only, and the fast C++ verifier itself carries no formal guarantee - the Lean one does), but it is the first open system in a plausible range, and auditable rather than trust-us crypto.

Mistral Large 4 technical report: 1T-parameter open MoE, and the agentic penalty perplexity hides

ResearchWeb

Mistral published the Large 4 technical report with the open weights: 52B active / 1T total parameters, scoring 19.7% on FrontierCode 2.0, 41% on Terminal-Bench 4.0, and 50.9% on the Artificial Analysis Cyber Index, with NVFP4 quantization shrinking the checkpoint to 606 GB so it serves on four GB300 GPUs; multiple-teacher distillation gives high/medium/low reasoning-effort modes. The report's most useful finding is architectural: stacked KV-cache savings (sliding-window attention, cross-layer attention, YOCO) cut cache size 16x and looked fine on perplexity and MMLU - but quietly degraded long-horizon agentic performance, an 'agentic penalty' that standard metrics missed until SFT-stage evals surfaced it.

Why it matters: Two builder takeaways: perplexity and knowledge benchmarks can certify a model that is actually worse at agentic work - evaluate on the workload, not the proxy, which is the same lesson sys1-eval measured last week. And a 1T open model that serves on four GPUs with tunable reasoning effort changes the self-hosting math for frontier-class coding and security workloads.

Kimi K3.1 Pro open weights land on Hugging Face: 2.8T MoE, 1M context, near-frontier coding

ModelsWeb

Moonshot released the Kimi K3.1 Pro weights on November 4, on the day it promised: a 2.8T-parameter MoE with 104B active per token (16 experts), a 1M-token context window, and Gated DeepSeek Sparse Attention replacing full-attention MLA layers for long-context efficiency. Post-trained from K3 with much larger joint RL across hundreds of domains, it scores 65.7% on Terminal-Bench 4.0 - ahead of GPT-6 Astra (58.2%) and just behind Claude Opus 5.5 (66.4%) - and Moonshot reports claim-level hallucination on its hard factual stress bench down from 23.4% (K3) to 8.3%. Available on the Kimi API with a Highspeed variant; tech blog has the full eval table (internal benchmarks are theirs).

Why it matters: This is the strongest open-weight agentic coding model you can actually download today, and the second 1T+-class open release in two days alongside Hy4 - the open frontier is closing on the proprietary one, which changes the build-vs-call math for agent products. The architecture notes (gated sparse attention for 1M context) and the RL-at-scale stack description are worth reading even if you never run it.

Evaluating and Improving Agentic Applications: DeepLearning.AI x Arize course on trace-driven evals

CraftWeb

DeepLearning.AI launched a new short course with Arize AI, taught by Laurie Voss (npm co-founder, now Arize dev rel): read your agent's traces to find recurring failure modes, turn them into a test set you can rerun after every change, automate scoring with code and LLM judges you validate, and gate every change on the evals so each edit provably helps. The framing is right: traditional tests confirm code works, but agent failures hide in decisions and actions, so the test set has to come from observed behavior.

Why it matters: This is the same methodology the sys1-eval pick and Tuesday's harness course keep circling: evals derived from real traces, not vibes. Her capstone's evaluation loop - failure taxonomy from traces, rerunnable test set, judge validation - is exactly this pipeline, so the course is a structured walkthrough of the workflow she is already building. Free to audit; worth the few hours.
