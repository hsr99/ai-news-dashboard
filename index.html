Pick of the week

RudderStack's Jev shadow test lost to its one-loop agent

RudderStack ran a month-long shadow experiment across about 9,600 comparable real decisions. Jev answered for about $0.00015 in under 0.1 seconds, but the evidence-gathering LLM around it made the full pipeline 7% costlier and 60% slower than the existing one-loop agent.

The practical rule: put a typed decision model where the evidence is already in the prompt, such as a final reviewer or routing check. Do not split gather and decide just to make the final choice cheap. RudderStack has not yet shown that a tuned Jev chooses as well as its production agent.

GLM-5.4 loops 28 layers twice at 750B scale

Models Web

Z.ai launched GLM-5.4, its first flagship Loop Transformer. It runs 28 layers of the GLM-5 base model for two iterations at the 750B scale, with per-token gated updates, a hybrid global-plus-sliding-window KV cache, and sparse attention index reuse to keep the second pass affordable. Z.ai claims intelligence comparable to 2T-3T models, up to 200 tok/s off-peak and 70-80 tok/s at peak load; its 30B iso-parameter ablation also cut average thinking length by 10-14% on most benchmarks.

Why it matters: This is another signal that repeated depth may buy reasoning without storing more weights, following last week's Inkling work. Treat the headline capability as a vendor claim: the public post has the architecture and a 30B ablation, but no GLM-5.4 model card or benchmark table. API access is listed as coming soon and open weights are waiting on safety hardening, so the useful next check is independent coding quality, loop latency and cost per completed task.

OpenRouter removes three providers and 125 ZDR endpoints

Industry Web

OpenRouter said researchers found that some inference providers had data compromised or were not upholding their stated data policies. OpenRouter off-boarded three providers, removed 125 endpoints from Zero Data Retention eligibility, notified potentially affected customers, and started ongoing policy tests plus network-path verification. OpenRouter says the findings did not show a breach or unauthorized access to OpenRouter itself.

Why it matters: If you route production prompts through a model marketplace, ZDR is a per-endpoint operational claim, not a permanent property of the platform. Check whether your account was notified, pin sensitive traffic to providers whose policies you have reviewed, and keep an incident path for endpoints that silently lose ZDR eligibility. The provider-specific notices are linked from OpenRouter's post.

RudderStack's Jev shadow test lost to its one-loop agent

Agents Web

RudderStack split a one-loop production agent into an evidence-gathering LLM step plus Jev decision calls. Jev itself did what it promised: under 0.1 seconds and about $0.00015 per decision. But over roughly 9,600 comparable real runs, the full shadow version took 7.2 seconds against 4.5 and cost $0.00411 against $0.00383, about 7% more. The evidence step cost about as much as the whole existing agent.

Why it matters: This is the useful decision-model production lesson: the final choice is often not the expensive part. About three-quarters of RudderStack's cost was reading context and tool results, so a typed judge pays when the evidence is already in the prompt, such as a final reviewer, not when another LLM must run the tool loop first. The post is honest about the remaining gap: it did not establish whether a tuned Jev chooses as well as the current agent.

Hugging Face turns agent evals into maintained software

Craft Web

Hugging Face's new guide walks through building and maintaining an agentic evaluation: define the claim, reuse a task, run it unchanged, adapt it, check the eval, read traces, report the score, and compare models. Its example reuses Harbor and Terminal-Bench, builds eight synthetic Raman-lab tasks, and separates pass@3 (7/8 tasks passed at least once) from pass^3 (1/8 passed every time). It also shows how traces exposed 19 of 24 rollouts that declared completion before useful output.

Why it matters: This is directly useful for capstone and production eval design. Score what changed in the environment, not what the agent claims; make the oracle pass, the no-op fail, and a shortcut fail; read traces before publishing a score; and report uncertainty plus known benchmark flaws. The guide's checklist for what to open, what to protect, and when to refresh tasks is a good template for an eval that has to survive real use.

vLLM shows NVMe can replace the DRAM KV tier

Craft Web

A vLLM/MoRI serving test put a 1.8TB agent KV pool on two local NVMe drives, using only about 80GB of DRAM for write buffering and read staging. On replayed Claude Code sessions, Kimi-K3 throughput stayed within 1% of a same-size DRAM pool at 48, 70 and 96 concurrent sessions. The argument is retention: Kimi-K3 wrote 2.3-4.6TB of KV an hour, so a 1.8TB pool held only 23-47 minutes regardless of medium, while NVMe makes longer retention cheaper.

Why it matters: For agent serving, throughput followed KV hit rate more than pool latency because asynchronous loads finished while requests waited for prefill. The actionable model is to size the pool from session pause times and write rate, not just buy the fastest memory. Caveats are explicit: tests used AMD MI355X nodes, Kimi-K3 and DeepSeek models with low KV per token, many key runs were single runs, and NVMe is unproven where the pool serves most prompt tokens.

Claude Ship can review, fix and approve PRs under repo policy

Agents Web

Anthropic launched Claude Ship in beta: Code Review checks PRs, PR Steward responds to failing CI, merge conflicts and review feedback, and Claude Approvals applies a policy file to decide what can merge. Developers can start with /ship in Claude Code; admins can enable one repository at a time, set review depth and spend limits, and run Approvals in observe-only mode. Anthropic says its own merged PRs more than doubled from June to September while the share reverted fell by more than 40%, an internal vendor metric.

Why it matters: This moves agents from writing code into the review and release path. The safe adoption shape is explicit: start in observe mode, keep branch protection and required checks, write an approval policy like a stricter CODEOWNERS file, and exclude security-sensitive paths from autonomous approval. Claude Ship is token-billed, and it is unavailable to organizations using Zero Data Retention, the HIPAA configuration or customer-managed encryption keys.

OpenAI and Cisco open-source Shirudo for live Linux shields

Industry Web

OpenAI and Cisco released Shirudo, an open-source runtime for temporary eBPF protections while patches are prepared. Shields are cryptographically signed, checked by the Linux eBPF verifier, deployed without restarting the target, and recorded with TPM-backed verification. In a controlled Java4Shell test, a Codex-generated shield added a Base64 input check to a running Elasticsearch process and blocked the exploit while the service stayed up.

Why it matters: This targets the gap between knowing about a vulnerability and safely patching every host. The useful pattern is mitigation as a testable artifact: generate a narrow shield, monitor its effect on real traffic, require operator approval, then remove it after the permanent patch. It is early infrastructure, not a patch replacement; try the VM quickstart or a canary before letting any agent propose kernel-level controls.

John Snow Labs ships medical decision models for private deployment

Agents Web

John Snow Labs launched Medical DM Small and Nano, clinical-text decision models that return a fixed answer and probability instead of generated text. The vendor reports composite scores of 0.917 and 0.901 across nine clinical task areas, about 40ms and 24ms per note, and private deployment on premises or in AWS, Azure, Databricks and Snowflake. A separate PHI Guard model screens de-identified notes on CPU. The models are available to existing customers for private deployment.

Why it matters: This is the Jev pattern going vertical: small typed models for high-volume judgments inside a regulated data boundary. The cost and latency could make review-every-record workflows practical, but the comparison set, pricing and weights are not public, so treat the accuracy and GPU-cost figures as vendor claims. For healthcare or enterprise data, test calibration and abstention thresholds on your own notes before routing low-confidence cases.

Gemini API slices Office files, PDFs and media server-side

Agents Web

Google added native file slicing controls to the Gemini API across all Gemini 4 models, plus direct upload support for Office and OpenDocument files. A Files API URI can be reused across turns while the caller or agent requests a page range, sheet tab and cells, video interval, resolution, frame rate, or content layers such as text, formulas, transcript, frames and audio. Google says tokens are billed only for the portions the model inspects.

Why it matters: This removes a common agent-harness failure mode: running LibreOffice, PDF renderers and ffmpeg locally just to make a file small enough to inspect. The better pattern is skim cheaply with extracted text or low-resolution previews, then zoom into the exact page, sheet or frames at high resolution. Check file retention, residency and the actual token bill on your own workload, but this can materially simplify multimodal document agents.

Two CodeClimb builds separate durable agents from convenient agents

Craft Web

Paul Iusztin built the same overnight coding agent, CodeClimb, on Inngest and on LangGraph plus LangSmith. Inngest's separate state server could notice a dead worker, resume from the last experiment or evaluation, pause for a human without holding a worker, and clean up through a later event. LangChain's Agent Server was easier to deploy and observe, but its one-second durability batching, in-process retries and whole-run sweeper meant a crash could lose recent work and leave sandboxes running unless the author added a watchdog.

Why it matters: If you use LangGraph in production, do not confuse checkpoints with full crash recovery. Wrap every side effect in a named step, keep step inputs and outputs small, make cleanup a queued task rather than a process-local hope, and test a worker kill mid-run before trusting an overnight agent. The comparison is hands-on and relevant, but Inngest sponsored it, so verify the durability and cost claims on your own workload.
