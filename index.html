Pick of the week

Karpo Decision 31B opens a one-pass Jev-class model

Karpo Decision 31B is an open-weight multimodal decision model fine-tuned from Gemma 4 31B. It reads a state and typed questions over text, JSON and images, then returns every option probability in one forward pass without generating text. The Hugging Face card lists 31.3B BF16 weights, Apache-2.0 code and weights, a 62.5GB download, and a System One-compatible interface.

This is the week's most testable decision-model release: the Decision Index maintainers score it 73.9 Full, tied for first among 300 entries, and JevBench scores it 87.2, third among 243 Jev-class open-weight models. Karpo reports 95 ms median latency on one RTX PRO 6000, but long prompts can take seconds and the cost score is estimated from GPU time. Recalibrate thresholds on your own base rates; the release itself warns that fixed probabilities drift when deployment class balance changes.

Qwen4-Max: 2.4T flagship, 71B active, 1M context

ModelsWeb

Alibaba released Qwen4-Max through QwenCloud, with native image and video understanding, a 1M-token context window, tool calling, structured outputs, and OpenAI Chat Completions, Responses and Anthropic Messages compatibility. It is a 2.4T-total MoE model with 71B active parameters per token; smaller Qwen4 open-weight releases are promised, but Qwen4-Max itself is cloud-only for now.

Why it matters: This is the day's biggest model launch and the clearest cost claim: Alibaba says Qwen4-Max uses 35% fewer tokens and cuts average cost per task by about 60% versus Qwen3.8-Max on its proprietary Work360 suite. Treat the benchmark and 48-hour agent demonstrations as vendor evidence. The 71B active count is compute, not resident memory: 2.4T weights would still require roughly 1.2TB at 4-bit if weights ship later, so plan around API access rather than single-node local use.

Listed API pricing is $0.003 per million cached input tokens, $0.070 input and $0.281 output; Tencent says OpenRouter support is coming, with free WorkBuddy use and 50% TokenHub API discounts through Nov 30.

Perplexity Decider v1.3 opens Jev-style decisions with Locate

AgentsWeb

Perplexity released Decider v1.3, built on Qwen3.8-27B, and Decider Flash v1.3, distilled to Qwen3.5-4B. Both answer yes/no, choice and score questions with probabilities; the new Locate mode extracts verbatim spans with character offsets and confidence. Hugging Face lists both repos as public and ungated under Apache-2.0, and the models also run through OpenRouter and Perplexity's Decisions API.

Why it matters: This is directly in the Jev-shaped lane the capstone tracks, with usable weights and a structured extraction primitive. Perplexity reports 91.6% zero-shot accuracy across 63 internal classification tasks, better results than Jev 1.14 in most suites, and one internal day where Decider reviewed 1B tokens across 7,000 agent sessions and surfaced 14 security-rule fixes. Those are vendor evaluations, but the open weights make local calibration tests possible before routing production traffic.

Controlled study: small decision heads match 27M schemas

ResearchWeb

The Nov 13 paper re-implements five typed-decision readouts under one protocol: Qwen3-0.6B, 15 public English training sources, one recipe and one seed. Every head lands at 81.3-82.0% in-domain; a 0.5M-parameter cosine head matches a 27M-parameter joint-schema head in-domain at half its measured inference time. Joint prompts also match per-question prompts while running 1.6x faster at inference and 2.1-2.5x faster in training.

Why it matters: For a small decision model, the practical recipe is to spend effort on the backbone and keep the head minimal: moving to Qwen3-4B adds four points in-domain and eleven on held-out sources, while base, instruct and thinking checkpoints tie. The limits are clear: one seed, English data, single-H100 batch benchmarks rather than API latency, and no reverse-engineering of Jev's unpublished architecture or training data. The promised code repository was not publicly resolving when checked.

Liquid d1.2 adds audio, spans, boxes and multi-select answers

AgentsWeb

Liquid released d1.2 and d1.2-ultra as hosted decision models with zero generated tokens. Both accept text, images and audio, allow 65,536 input tokens per question, and add five answer types: exact values, spans, image boxes, numeric estimates with ranges, and multi-select choices. Treat the five new-task numbers as internal held-out tests until outside reproduction lands, and count image or audio tokenization plus the state read in any cost comparison.

GPT-6 Astra helped build a candidate lattice Standard Model

ResearchWeb

OpenAI's first science guest post describes Nathaniel Craig's October preprint, A gauge-invariant measure for lattice chiral fermions. Craig had the refinement strategy; he says GPT-6 Astra suggested how to map force fields onto finer grids, showed the comparisons converged, and took the lead on the detailed proof. Outside lattice theorists reviewed the proof and asked follow-up questions before the post.

Why it matters: This is a concrete frontier-model science result, not a benchmark screenshot: the proposed construction could answer a decades-old obstacle to defining the full Standard Model nonperturbatively on a lattice. It remains a candidate in a preprint, with reflection positivity and the continuum limit still open, so treat it as expert-reviewed work in progress rather than a solved theory. The useful read is the workflow: human strategy, model-led proof development, then domain-expert challenge.

Evolving Infra adapts LLM serving to agent workloads

CraftWeb

Evolving Infra targets agent traces where long pauses, branches, sub-agents and compaction break static prefill-decode splits. Its nodes can switch between prefill and decode, an online planner follows workload composition, and an agent-aware distributed KV manager uses context-management signals for eviction and transfer. The implementation is open source.

Why it matters: The production lesson is that agent serving needs workload state, not just request metrics. Across coding, math and computer-use workloads with GLM-5.2 and Kimi K2.6 on up to 256 GB300 GPUs, the authors report up to 4.1x lower mean end-to-end latency and 14x lower P95 time to first token than NVIDIA Dynamo. Treat this as large-cluster evidence from the authors, not a single-GPU recipe; the useful small-team move is to preserve branch state and reuse signals in traces and cache policy.

Treat inference-stack changes as model changes

CraftWeb

Acetrum's field note pulls together Ekka's catalogue of 90 real silent errors in vLLM and SGLang and a reproducibility study where backend choice alone shifted benchmark scores by up to 16.6 points. Its release rule is blunt: framework versions, quantisation, tensor parallelism, kernel backends, dtypes and cache settings all go through the same quality gate as a new model checkpoint.

Why it matters: The actionable gate is cheap: keep a boring reference configuration, replay a few hundred real production inputs, count exact answer disagreement before aggregate scores, record framework and backend details in every trace, and stop rollout when the quality delta crosses a preset margin. The 16.6-point swing is a worst cell in public benchmarks, not a universal rate, so verify your own workload. The primary Ekka and backend papers back the underlying risk.

Hugging Face now routes open-model inference through OpenRouter

IndustryWeb

Hugging Face switched Inference Providers for language models from its custom router to OpenRouter. A Hugging Face token can now call every provider-served open-weight model on the Hub through the same API, while OpenRouter chooses among 80+ providers using live price, speed and reliability measurements and retries failed calls on the next provider. Model pages add Providers and Metrics tabs showing per-provider price, throughput, latency, context and uptime.

Why it matters: This makes open-model routing substantially easier to test without managing separate provider accounts, and it directly strengthens the OpenRouter integration lane. Hugging Face reports no markup and unchanged provider pricing, but there is one breaking change: custom provider keys no longer work for language models routed through the HF bill. OpenRouter's reported routing gains, including 46% fewer capacity errors and 16.9% better time to first token, are operator measurements rather than independent benchmarks.

Verify AI-generated PRs against acceptance criteria, not vibes

CraftWeb

Sonar's new verification guide lays out a usable pre-merge sequence: document what the change must do and what it may touch, inspect the diff for scope creep, invented APIs and unnecessary dependencies, run independent static, type, secret and dependency checks, map tests to acceptance criteria with negative cases, and require both contextual review and enforced branch protections. After fixes, rerun the full pipeline and keep the evidence with the PR.

Why it matters: The useful rule is separation of duties: an agent can self-check, but verification should use a different method from the one that wrote the code, and high-risk changes still need human approval. This is a vendor guide with a product pitch at the end, so skip the tool positioning and copy the checklist shape: requirements first, deterministic checks second, contextual review third, merge gates always. LeadDev's current report shows why this is urgent: 45% of surveyed engineering leaders now call code review capacity their biggest delivery bottleneck.
