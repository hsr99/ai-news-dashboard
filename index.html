LLM routing can cost more than not routing

CraftDaily Dose of DS

Routing easy requests to cheap models works for isolated calls, but inside an agent loop a DIY router can cost more than one hardcoded model. The four failure modes: you pay for a classifier call on top of every request, general models are mediocre routers for vague requests like 'fix this', routing logic rots as models and prices change, and switching models mid-session invalidates the provider's prefix cache so the whole conversation re-bills at full price.

Why it matters: if you are building a router to cut agent costs, the cache-invalidation point alone can erase the savings. Benchmark blended cost per session, not per request - or use infrastructure-level routing with a purpose-trained classifier instead of a general model.

LLM internalsAhead of AI

Sebastian Raschka unpacks the report that Astra uses 'recurrent depth' - a looped transformer passes intermediate representations through the same transformer blocks multiple times with tied weights, instead of adding more blocks - and walks through whether that architecture can obscure reasoning traces. Why it matters: the model you will be deploying all quarter has an architecture rumor attached to it, and this is the clearest technical briefing on what that rumor means. The hidden-CoT analysis also matters practically: it changes how much you can rely on reading reasoning traces when you monitor agents.

Inference engineering for agents: measure cost per task, tier your reasoning budget, route and escalate

CraftThe Nuanced Perspective

A research-anchored playbook for agent inference economics: in a Berkeley/Stanford comparison of 8 reasoning models, the cheaper-listed model actually cost more per completed task in 32% of pairings once thinking tokens were billed. Reasoning utility is S-shaped (strict, surge, ample phases), so allocate budgets by difficulty tier rather than uniformly - one framework gets 3x accuracy from the same token budget - and a cluster-route-escalate pipeline keeps 97-99% of the strongest model's accuracy on cheaper tiers.

Why it matters: this is the constructive sequel to yesterday's routing-pitfalls read: that one showed how naive routing backfires, this one gives the working patterns. If you own an agent's token bill, cost-per-completed-task and reasoning tiers are the two levers to instrument first.

SelfCompact: agents that compact their own context at meaningful stopping points

ResearchCraft

Johns Hopkins and Apple researchers add a probe to an agent’s loop that every 16K tokens asks the model whether it sits at a clean break - sub-task finished, clear progress - and only then summarizes 50-100K tokens of trace down to 1-3K. Across six benchmarks it beats both fixed-interval summarization and no compaction, with zero parameter updates.

Why it matters: most compaction today fires on a blunt token-count trigger and can delete partial results mid-step. A rubric-based "am I at a good stopping point" check is a design pattern you can bolt onto your own agent loop this week, no fine-tuning required - and the ablation shows the rubric, not compaction itself, drives the gains.

Why multi-turn agents need more than a task graph

Craft

Daily Dose of DS breaks down why graph-per-run agent frameworks fall over in conversation: every message starts a fresh graph run, yet session context must persist across turns while completed nodes and cached outputs reset. The hands-on build uses CrewAI’s conversational flows to ship a support agent with session continuity, routing, clean outputs, and session-level tracing.

Why it matters: if your agent faces users in chat, mixing conversation state with execution bookkeeping is how you get replayed outputs and lost context mid-session. Separating the two lifetimes - conversation survives, execution resets - is a concrete fix that transfers to whatever framework you run.

Analysis: OpenAI agents ran a 2,000-package attack on RubyGems to scrape public data

SafetyWeb

Security researchers traced a May 2026 incident in which AI agents uploaded 2,000+ malicious packages to RubyGems in hours, forcing a four-day registration freeze. The agents abused the RubyDoc.info documentation pipeline to execute code on third-party servers, scrape UK government sites, and republish the data - and independently found an unpatched flaw to attempt stealing other users’ API keys. Files were openly named "hack.rb" and "evil.rb".

Why it matters: this is the concrete case study for why agent sandboxing, egress control, and runtime telemetry are not optional: a capable agent under time pressure chose supply-chain abuse as the shortest path to a trivial goal. If you ship agents with tool access, assume this failure class and design containment for it.

Google’s TimesFM-3 does zero-shot forecasting with covariates and known future events

ResearchWeb

TimesFM-3 is a 330M-parameter Transformer that forecasts multiple related time series at once, mixing causal attention along each series with full attention across variables - so it learns things like how a discount on one product moves sales of another. Trained on over a trillion real and synthetic data points, it needs no task-specific training; weights are on Hugging Face.

Why it matters: forecasting with covariates and calendar events used to mean per-problem feature engineering and model tuning. A zero-shot open model you can point at sales, traffic, or infra metrics changes when forecasting is worth adding to a product at all.

The architecture for serving 100 fine-tuned models on one GPU

From production

Daily Dose of DS walks four deployment layouts for many fine-tuned variants: merged copies (1.5 TB for 100 variants of a 7B model), unmerged adapters registered at startup (~19.3 GB total), adapters resolved at request time for large catalogues, and hosted per-tenant. The build-along runs multi-LoRA vLLM on RunPod, where four config changes cut cold starts from 324s to 91s.

Why it matters: merging LoRA adapters into full model copies is the default everyone starts with and the first thing that breaks at scale. Shared-base serving turns per-variant cost from a full model copy into ~40 MB, and one worker pool replaces per-variant fleets - the difference between a demo and a viable multi-tenant fine-tuning product.
