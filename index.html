Anthropic's threat report: autonomous exploit foundries and AI supply-chain attacks are here

SafetyWeb

Anthropic says a majority of the cyber operations it disrupted now used AI for direct execution or orchestration, not just advice. A Chinese-speaking group ran parallel agent swarms with persistent campaign memory and a continuous binary-reversing/exploit loop; other attackers targeted AI evaluation sandboxes, LiteLLM deployments, and wrappers to steal production API keys.

Why it matters: secure the whole agent system, not only the model prompt. External inputs need hostile-data treatment; tool workers need isolation and bounded authority; API keys and sessions need the same controls as production credentials.

Two silent AutoRound mistakes - and why your calibration corpus is part of the quantizer

CraftWeb

The Archsloth team had optimized with AutoRound's W4A16 scheme, then exported Q4_K_M, so the exporter quietly rebuilt a different quantization and discarded most of the search. Matching the scheme and enabling SignRoundV2 cut KL divergence from the bf16 teacher by 21-54% across ten language/code axes at the same file size; calibration language and sample interleaving materially changed results.

Why it matters: a valid artifact and falling loss curve do not prove the quantization path you intended actually shipped. Match search and export schemes, test monotonicity, measure distribution drift rather than perplexity alone, and version the calibration corpus like code.

Agent observability that closes the loop: instrument, investigate, fix, prove

From productionWeb

Honeycomb's practical loop starts with OpenTelemetry spans for every model call, tool call, and handoff. Three fields - gen_ai.conversation.id, gen_ai.agent.name, and gen_ai.operation.name - are enough to reconstruct a multi-agent run; versions, tokens, finish reasons, tool I/O, and eval scores make failures, cost, and regressions queryable.

Why it matters: do this before production traffic. A readable trace is the difference between debugging one weird transcript and finding a repeated failure pattern, tying it to a release, and proving the fix helped without moving cost or quality the wrong way.

ShadowPEFT turns a tiny persistent model into the adapter

ResearchToolsWeb

Instead of injecting low-rank deltas into a frozen base model, ShadowPEFT runs a much smaller trainable model beside it and fuses persistent task state into each base-model block. It is now in Hugging Face PEFT; on Llama 3.2 3B / GSM8K it reached 48.1% versus LoRA's 46.9%, with a 26 MB checkpoint but higher peak memory from the second forward path.

Why it matters: adapters no longer have to look like weight patches. A detachable shadow path can carry task behavior and even run alone for cheap inference, but benchmark memory and latency because the dual path is not free.

ResearchCraftWeb

On AppWorld, a GPT-4.1 ReAct agent averaged 77.4% across five runs but passed all five runs on only 53% of tasks. IBM's Consistency Analyzer resamples each recorded decision point without replaying tools or needing ground truth; guidelines from the unstable steps raised Pass^5 to 69% while average accuracy also improved.

Why it matters: report Pass^k beside Mean@k. An agent can be capable and still unreliable, even at temperature zero; use trace-level resampling to find flat decisions before a demo or production workflow finds them for you.

CraftResearchWeb

Text watermarking can shift refusals and agent tool calls

SafetyResearchWeb

Tests of Hugging Face's SynthID-Text implementation across six open-weight models found that watermark tournament sampling changed refusal behavior, especially under prompt injection, and changed which tools and arguments agents selected. Red Hat's CI detector catches LLM serving regressions before release

From productionServingWeb

Red Hat benchmarks each upstream vLLM release and compares it with downstream production images across hardware, checking time to first token, throughput, inter-token latency, and task accuracy. A fixed 5% threshold produced noisy false positives, so the detector adds Wasserstein distance to ask whether the whole request distribution moved rather than overreacting to one median or percentile.

Why it matters: container, dependency, kernel, and hardware changes can pass functional tests while silently hurting inference. Store an upstream baseline per hardware target, test release candidates at several concurrency levels, and use distribution shift as a second opinion before blocking a release.

CraftAgents

Two Codex escapes show why sandbox enforcement must stay outside the sandbox

SafetyFrom productionWeb

Researchers escaped Codex’s strictest mode by reading a privileged token from the same Node heap as untrusted code, then escaped workspace-write mode by making apply_patch widen its own permissions from attacker-supplied paths. OpenAI reportedly fixed Heapjack in Desktop 26.818.21641 and Overpatch in CLI 0.149.0 within eight days.

Why it matters: V8 contexts isolate globals, not memory, and a tool cannot safely calculate its own authority from untrusted input. Put capability checks in a separate process or kernel boundary, validate canonical paths outside the tool, avoid shared secrets across trust zones, and update affected Codex builds.

Fourteen production days show prefix cache, not peak throughput, runs agent inference

From productionServingWeb

Scalably served 28,097 long, repetitive agent requests with Qwen3.8-27B NVFP4 on two RTX 5090s: 82.6% of prefilled tokens hit prefix cache, median TTFT was 0.61 seconds, and only two preemptions occurred after reserving 8% of KV blocks. The queue knee appeared near 12 running requests, so a gateway admitted at most ten and spilled excess work to cloud before dispatch.

Why it matters: Design for your prompt shape, not a fixed-prompt benchmark. Track cache hits, KV use, preemptions, queue wait, and stale telemetry; reserve cache headroom and choose fallback before an SSE stream opens. A faster MoE still lost the job because replayed tool decisions and recovery behavior were worse.

SoL-Pi searches the harness layer for token efficiency

ResearchAgentsCraftWeb

Across roughly 150 proposed changes, 500 environments, and 3,000 runs, SoL-Pi retained four mechanisms: fuse a mutation with its follow-up command, compact only when projected savings beat rewrite cost, replace repeated large observations with stable handles, and reduce logs with verified quotes plus fallback. On 51 public EdgeBench tasks, the complete stack cut recorded token traffic 44.7-49.0% across GPT-5.6 Sol and Opus 5.

Why it matters: Optimize the loop around the model with fixed capability gates and held-out tests. The efficiency setting is a tradeoff, not a free win: under GPT-5.6 Sol it kept 93.7% of Pi’s average score while using 49% fewer tokens; a single-mechanism performance setting slightly improved score with much smaller savings.

A coding-model bake-off can reverse when the harness changes

AgentsCraftWeb

A detailed analysis of a 176-setting ablation reports that context management moved one model from 6.4% to 58.4% on SWE-Bench Verified at 32k, while switching between full file tools and bash-only reversed the winner between two models. Planning helped a weaker model’s accuracy but mainly constrained cost for stronger ones.

Why it matters: Version the tool list, planning policy, compaction strategy, context budget, and retries alongside every model evaluation. Compare cost per resolved task on your code, then re-tune after a model swap. This is secondary analysis of a new study, and some reported gaps are small enough for benchmark noise, so reproduce the direction before buying on it.
