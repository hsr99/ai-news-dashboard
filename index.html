Pick of the week

Claude now writes proofs that its code is correct

Anthropic's Frontier Red Team and Theorem had Claude formally verify existing software: ~180M lines of machine-checked proof for 123 OSS-Fuzz libraries in weeks, catching hundreds of bugs conventional testing missed, including a decade-old logic error and a year's worth of one PDF reader's security bugs in one week.

Why it matters: Formal verification used to cost 20 person-years for one small kernel; AI proof generation makes "proven correct" a plausible default for AI-written code, which changes how much review generated software needs. Limits are real: proofs hold for one architecture, single-threaded programs, inputs under 64 MB, and individual proofs burn hundreds of millions of tokens.

Apple pools idle Macs into a GPU cloud for ML inference

CraftFrom productionWeb

Apple's Minions paper describes a dynamic virtual GPU cloud that schedules ML inference across idle Apple Silicon Macs, with a metadata store, executor and watchdog for fault tolerance. In Apple's deployment, jobs that could wait more than ten hours for centralized GPUs could often start within minutes.

Why it matters: The useful pattern is overflow capacity, not new hardware: use local idle accelerators only when placement, health checks and failure handling are explicit. This is an internal Apple system and operational experience, not a product you can deploy; reproduce the queue-time result on your own device fleet before relying on it.

Kubernetes autoscaling now has to reason about GPU topology

CraftFrom productionWeb

The CNCF post from AWS engineers argues that the old split between pod scheduling and node autoscaling breaks down for accelerator-heavy AI workloads. A pod can stay pending even while aggregate capacity exists because the autoscaler may add a node whose topology or device layout the scheduler cannot use.

Why it matters: When serving GPUs, track pending time, stranded capacity and placement constraints separately instead of treating scale-out as one counter. The post is architectural guidance, not a benchmark; use it to check whether your autoscaler understands topology, locality, disruption policy and accelerator-specific provisioning delays.

Siddhant Khare's field guide pulls together agentic-inference measurements showing 94-99% prefix reuse during tight tool loops, but only 18% after a one-hour pause in one public trace. llm-d 1.0 makes distributed inference agent-aware

CraftFrom productionWeb

Google, Red Hat, IBM and a 25-organization community released llm-d 1.0, an open-source Kubernetes-native stack for coordinating vLLM and SGLang replicas. It combines prefix/session-aware routing, tiered KV cache, flow control, disaggregated prefill/decode serving and safer rolling upgrades for mixed TPU and GPU fleets.

Why it matters: Multi-step agents share prefixes, arrive in bursts and should not starve interactive users. Use llm-d's model as a checklist: route by cache and session, tier KV state, and enforce priority before adding replicas. Google's 85%+ median TTFT reduction and 2.4x throughput are vendor benchmarks on one coding workload, so reproduce them on your traffic.

Microsoft gives agents permissions that can shrink mid-task

SecurityAgentsWeb

Microsoft is extending Project Perception with Dynamic Permissions, Dynamic Agent Risk and Dynamic Conditional Access for agents. The controls can scope authority to a task, revoke it when the task ends, preserve reads while blocking writes, require verified approval for consequential actions, or isolate and stop a risky runtime.

Why it matters: Do not let an agent inherit its user's standing access or act as its own security boundary. Give it a separate identity, task-scoped authority and independent evidence that can tighten policy as behavior drifts. This is Microsoft-stack guidance, but the control pattern applies to any enterprise agent platform.

From productionMLOpsWeb

vLLM's Elastic Expert Parallelism now prepares joining workers asynchronously and expands expert-parallel communication in place. In its DeepSeek V4 Pro benchmark, scaling from 16 to 20 GB200 GPUs cut downtime from 99.62 seconds to 0.82 seconds; scaling back took 1.96 seconds, while a full restart took 197 seconds.

Human-in-the-loop agents need durable execution, not chat history

CraftAgents

Daily Dose of DS walks through the failure mode of agents that pause for human approval: by the time approval arrives, the process and its state are gone, and a naive re-run creates a fresh operation with different retrieved evidence or duplicated side effects. The piece builds a resumable RAG agent with Google's Agents CLI and ADK so the exact invocation, evidence and pending confirmation survive across processes.

Why it matters: If your agents pause for humans, model the run as durable state, not a chat transcript: persist the invocation, evidence and completed side effects so a resume is idempotent. Google's Agents CLI installs ADK skills for scaffolding, evaluation, deployment and observability into the coding agent you already use, so this is buildable today rather than a research idea.

Switching models mid-session can erase routing savings

CraftFrom production

Nhu Hoang's TDS analysis shows why LLM routing savings evaporate in practice: moving turn 8 of a conversation to a cheaper model forces that model to prefill the entire history from scratch at full price, a cold-cache operation that can dwarf the per-token savings. It cites Azure Research's August 2026 production study of 13.5M Copilot sessions and 760M model calls.

Why it matters: Route at session or task boundaries, not mid-conversation, and count the prefill a switch triggers, not just the token price difference. This pairs with Monday's prefix-cache field guide: cache locality, not list price, is the real cost driver for multi-turn workloads.

Beacon gives Claude Code, Cursor and Codex one shared memory

CraftAgents

Beacon, open-sourced by Asymptote Labs and demoed in Daily Dose of DS, gives Claude Code, Cursor, Codex and 20+ other coding harnesses a shared memory layer. It captures prompts, tool calls, commands and file changes via OpenTelemetry, hooks and local session files, normalizes everything into searchable traces, and lets a different agent resume where the last one stopped.

Why it matters: If you bounce between coding agents or hit a usage cap mid-task, cross-harness memory removes the silent restart cost, and it leaves a local, queryable record of what your agents actually did, which is useful for reviewing agent behavior. It is an early open-source project: check what session data leaves the machine before pointing it at client repos.

Claude now writes proofs that its code is correct

ResearchWeb

Anthropic's Frontier Red Team, with partner Theorem, had Claude verify existing software instead of writing new code: it translated crash tests from 123 OSS-Fuzz libraries into mathematical problems, analyzed the compiled machine code, and produced roughly 180M lines of proof in a few weeks, checked automatically by the Rocq verifier with almost no human review. Along the way Claude found hundreds of bugs testing missed, including a logic error undetected for over a decade, and as many security bugs in a widely used PDF reader in one week as it usually gets reported in a year.

Why it matters: Formal verification used to be reserved for avionics because 20 person-years bought you one small kernel. If models can generate machine-checked proofs, AI-written code can ship with evidence, not just vibes, and even a failed proof attempt surfaces real bugs. Keep the stated limits: proofs hold for a specific processor architecture, single-threaded programs and inputs under 64 MB, and individual proofs cost hundreds of millions of tokens, with no total cost disclosed.

Google's Harness² improves agents by rewriting everything except the model

ResearchAgentsWeb

Google Research open-sourced Harness² under Apache 2.0: instead of fine-tuning weights, the framework improves an agent by rewriting the plain-text components around the model - system prompt, guardrails, memory, skills, tool guidance, helper scripts, subagents and plugins. A task-level loop proposes edits and probes behavioral contrasts between runs, while a second loop carries what worked into future tasks. Paper: "Harness²: Recursive Agent Harnessing for an Open World" on arXiv.

Why it matters: For anyone shipping agents on API-only models, this formalizes what good teams already do by hand: treat prompts, tools and memory as the tunable surface, because the weights are off-limits. The behavioral-contrast trick matters where there is no answer key. It is a new framework with research-grade evidence, so expect rough edges and evaluate it against your own tasks before adopting the self-modification loop in production.

Replay production traces to grow your agent eval suite

CraftFrom production

Decoding AI's latest workflow attacks the "did my prompt tweak break last week's behavior?" problem: sample production traces, group the failures, and replay them against the agent with the exact same recorded tool outputs. Each reproduced bug becomes a deterministic regression case, and each fix gets re-verified against the replay before the case joins the eval suite.

Why it matters: This is the missing loop between observability and evals: traces tell you something failed, replays make it reproducible, and only then can a prompt or code change be tested against it. Directly applicable to capstone-style evaluation pipelines - the failure grouping step is where the judgment lives, so start with your highest-volume trace source.

Decision models are becoming the RAG gatekeeper

ModelsCraft

A new Daily Dose of DS build wires decision models into agentic RAG: Liquid AI's open-weight d1 family scores whether retrieved passages (text and images, via EmbeddingGemma 2) actually contain the answer, and the system generates a response only when evidence is sufficient, otherwise routing the question to human review. The pattern is the same one Jev and ScaleDown sell: small models that return structured judgments instead of prose. Liquid added vision to d1 on Oct 5.

Why it matters: This is the third sighting of the small typed decision-model pattern in two weeks (Jev, ScaleDown, now Liquid d1), which says the category is consolidating fast - relevant both for the capstone's evaluation angle and for Naama-style products that need a cheap, structured yes/no before spending generation tokens. Tutorial-grade evidence, but the build is reproducible and the models are open weights.
